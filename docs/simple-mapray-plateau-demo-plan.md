## 1. そもそも「PLATEAU」と「Mapray」は何が違うのか？

一番よくある誤解が「PLATEAUとMaprayのどちらを使うべきか？」という比較です。  
実際には、両者は競合するものではなく**「素材（データ）」と「再生エンジン（クラウド＆ビューワ）」**という関係です。

```text
┌─────────────────────────────────────────────────────────────┐
│ 【PLATEAU】（国土交通省）                                   │
│  ＝「都市の3Dオープンデータ（素材）」                       │
│  ・全国の建物、道路、地形の形状・属性データ（CityGML等）   │
│  ・データ量が非常に大きく、そのままではWebブラウザで動かない│
└──────────────────────────────┬──────────────────────────────┘
                               │
               Mapray Cloud で最適化・タイル配信
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 【Mapray】（ソニー / mapray社）                             │
│  ＝「大規模3D地理空間データをWebで動かすエンジン」         │
│  ・大容量のPLATEAUデータをクラウドでWeb用に自動最適化       │
│  ・ブラウザ（Mapray JS）上でカクつかずに高速レンダリング    │
│  ・ドローン等の動的データ（GPS座標）を簡単に重ねて表示     │
└─────────────────────────────────────────────────────────────┘
```

### なぜMaprayを使うと嬉しいのか？（通常Web3Dとの違い）

| 比較項目 | 通常のWeb3D（Three.js等で直接表示） | Maprayを使った場合 |
| :--- | :--- | :--- |
| **データの読み込み** | 対象エリアの3Dファイルを**一括ダウンロード**するため、範囲を広げるとブラウザが固まる・待たされる | クラウドから**視界に入る部分だけを自動で小分け配信**（LOD配信）するため、東京全域でも一瞬で表示が始まる |
| **座標・標高の扱い** | 緯度・経度・標高（DEM）を3D座標に変換する前処理が非常に大変 | **地球の丸み（WGS84）と標高データを標準装備**。GPS座標を渡すだけでピタッと重なる |
| **動的データの重畳** | ドローンの飛行位置や危険区域のポリゴンを自前で計算して描画 | MaprayのAPIで**「緯度・経度・高度」を指定するだけ**で簡単にドローンやハザードを表示可能 |

## 2. デモの基本コンセプト

> **「巨大なPLATEAUの都市データを、Webブラウザ上でこんなに手軽・サクサクに動かせて、箱庭ドローンがリアルタイムに飛ぶ！」**

複雑なベンチマーク数値や難しいアルゴリズムは見せず、**「見た目の軽快さ」と「ドローンが都市を飛ぶ楽しさ」**に絞ります。

## 3. デモの構成（シンプル2画面または切り替え）

デモは以下の**2つの見せ場**だけで構成します。

```text
┌──────────────────────────────────────────────────────────────┐
│ [見せ場1] 大容量PLATEAUデータの超高速表示                    │
│  ・東京タワー周辺から東京全体へスムーズにズームアウト        │
│  ・「普通の3Dなら固まるデータ量でも、Maprayなら一瞬で動く」  │
├──────────────────────────────────────────────────────────────┤
│ [見せ場2] PLATEAU都市空間を飛ぶ箱庭ドローン                  │
│  ・PLATEAUのビル群の間を、ドローン（3〜5機）がリアルタイム飛行│
│  ・箱庭（シミュレータ）のGPS位置情報がそのまま画面に反映     │
│  ・ワンクリックでドローン視点（追従カメラ）へ切り替え        │
└──────────────────────────────────────────────────────────────┘
```

## 4. 3分デモ台本（本番の流れ）

### 【0:00〜1:00】見せ場1: PLATEAUとMaprayの役割を説明
1. **画面**: 東京タワー周辺の綺麗な3D都市モデルが表示されている。
2. **トーク**: 
   * 「このリアルな建物の形は、国交省のオープンデータ**PLATEAU**です。」
   * 「PLATEAUは素晴らしいデータですが、東京全体だと何十ギガバイトもあり、普通はWebブラウザで手軽に表示できません。」
   * 「そこで**Mapray**を使っています。Maprayがクラウド側でデータを最適化し、ブラウザが必要な部分だけを瞬時に読み込むため、このようにサクサク動きます。」
3. **操作**: マウス操作で東京タワー周辺をぐりぐり回転させ、一気に東京全域へズームアウト。一切カクつかないことを見せる。

### 【1:00〜2:30】見せ場2: 箱庭ドローンとのリアルタイム連携
1. **操作**: 「ドローン運航開始」ボタンを押す。
2. **画面**: 3〜5機のドローンが出現し、PLATEAUのビル群をすり抜けるように飛行を開始。
3. **トーク**:
   * 「このドローンの位置は、バックエンドの**箱庭シミュレータ**からリアルタイムに届くGPSデータです。」
   * 「Maprayは地理座標（緯度・経度・高度）を標準で理解するので、シミュレータのデータを流し込むだけで、PLATEAU都市モデルの上を正確に飛ばせます。」
4. **操作**: ドローンを1機クリックして「ドローン視点（FPV/追従）」へ切り替える。ビル群を上空から見下ろす大迫力の映像を見せる。

### 【2:30〜3:00】まとめ
* **トーク**:
   * 「**PLATEAU（都市データ）** × **Mapray（Web配信・描画基盤）** × **箱庭（自律ロボットシミュレータ）** を組み合わせることで、Webブラウザさえあれば誰でも手軽に都市型エアモビリティのデジタルツインを体験できます。」

## 5. 実装を簡単にするための割り切り（やらないこと）

デモのシンプルさと開発スピードを最優先にするため、以下は**今回はやりません**。

1. **複雑なFPS/LongTask測定パネルの排除**:
   * 難しいグラフは見せず、画面右上に「60 FPS」「読込完了」とシンプルに表示するだけにする。
2. **機体数を30〜100機から「3〜5機」へ縮小**:
   * 画面がごちゃごちゃせず、1機ずつの動きやビルの間を抜ける様子がはっきり見える。
3. **複雑な3D Tilesローダーの自作を回避**:
   * Mapray Cloudに登録済みのB3Dデータ（東京タワー周辺・東京23区）を素直に使用する。
4. **複雑な障害物回避ロジックの簡略化**:
   * あらかじめ東京タワー周辺の安全なルート（Waypoints）を箱庭から配信する。

## 7. まとめ

*   **PLATEAU**: 国が提供する「都市の3D形状データ」
*   **Mapray**: その巨大なデータをWebで「一瞬で軽快に動かすエンジン」
