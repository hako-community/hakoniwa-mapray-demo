## 1. 結論：5km四方での比較は「完全に可能＆ベストな広さ」

5km四方（約25 km²）での比較は、技術的にも容量的にも**最も理想的な検証スケール**です。

1. **なぜ5km四方がベストなのか？**
   * **600m（狭い範囲）**: 通常のThree.js等でも軽快に動いてしまい、Maprayの優位性（クラウド最適化配信）が伝わりにくい。
   * **東京23区全域（広すぎる範囲）**: 無料枠10GBの制限に抵触するリスクがある。
   * **5km四方（絶妙な広さ）**: ドローンが都市を飛び回るのに十分な広域であり、通常方式では「読み込みの重さ・カクつき」が出始めるため、**Maprayの軽快さが圧倒的に際立つ**。

2. **Mapray無料枠（10GB制限）の安全性**:
   * **方法A（公式公開タイル利用）**: Mapray公式がホストする東京B3D（メッシュ `533935`, `533945`）を参照すれば、**自組織のCloud容量消費は 0 GB（無料枠を消費しない）**。
   * **方法B（自前Cloud登録）**: 5km四方に必要なCityGML（72〜77 GML）を自前アップロードしても**約3.7〜3.9 GB**であり、10GB制限に対して十分な余裕（約60%の空き）があります。

## 3. このデモで観客が一瞬で理解できる「3つの違い」

### ① データ読み込みの速さ（初期表示）
* **通常方式（下段）**: 5km四方の建物を読み込むために数秒〜十数秒のローディング待ちが発生。
* **Mapray（上段）**: 画面を開いた瞬間に視界内のタイルから即座に表示が始まり、待たされない。

### ② カメラ操作時のフレームレート（軽快さ）
* **通常方式（下段）**: 5km四方の膨大なメッシュ（数万棟）を一気に描画しようとするため、カメラをパン・回転した時にFPSが低下（カクつき）。
* **Mapray（上段）**: 距離に応じて建物の詳細度（LOD）を自動で最適化するため、広域を見渡しても高FPSを維持。

### ③ 広域を飛ぶドローンの追従性
* 同じドローン（3〜5機）が5km四方のビル群を抜けて遠くまで飛行。
* Mapray側では、ドローンがどこまで遠くに移動しても途切れることなく街並みがストリーミングされ、スムーズに追従できる。

## 4. 2分間デモ台本（シンプル＆インパクト重視）

* **【0:00〜0:30】前提の説明**
  * 「上段が**Mapray**、下段が**通常のWeb表示**です。どちらも同じ国交省PLATEAUの5km四方の都市モデルを表示しています。」
* **【0:30〜1:15】5km広域での操作比較（違いの証明）**
  * カメラを5km全体俯瞰から東京タワー近景へズームイン・ズームアウト。
  * 「下段の通常方式では、5km四方の膨大なビルデータを抱えるためカメラ操作でカクつきが出ます。一方、上段のMaprayはクラウド側で視界に合わせて賢く小分け配信するため、全くストレスなくヌルヌル動きます。」
* **【1:15〜2:00】箱庭ドローンのリアルタイム運航**
  * 3〜5機のドローンが5kmエリアを巡航開始。
  * 1機を選択して追従カメラに切り替え。「ドローンがビルの間をすり抜けて長距離を飛行しても、Maprayなら常に背景の都市が滑らかに追従します。」
  * **まとめ**: 「広域なリアル都市空間で自律ドローンをWeb上で可視化・管理するなら、Maprayのクラウド配信基盤が不可欠です。」
